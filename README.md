# Нейросетевой синтез фазового ДОЭ для 4 плоскостей — Nuclear IT Hack 2026

**Команда MEEFEE TEEM:** Тихон (капитан), Радомир.

Одна фазовая маска 128×128 восстанавливает 4 разных изображения на расстояниях 24,1 / 25,3 / 26,5 / 27,7 мм (λ = 532 нм, пиксель ПВМС 10 мкм). Расчёт идёт прямым методом дифракции Френеля с одним преобразованием Фурье, по формуле из условия.

## Запуск в Docker (для проверки)

```
docker build -t meefee-doe .
docker run --rm -v "<папка с комплектами>:/data/input" -v "<папка для результатов>:/data/output" meefee-doe
```

Windows (PowerShell), из папки репозитория:
```
docker run --rm -v "${PWD}\input:/data/input" -v "${PWD}\output:/data/output" meefee-doe
```

**Вход** (`/data/input`): либо 4 изображения (один комплект), либо подпапки по 4 изображения (несколько комплектов). Порядок изображений по имени файла = порядок плоскостей 24,1 / 25,3 / 26,5 / 27,7 мм. Любой размер и цвет приводятся к 128×128 grayscale.

**Выход** (`/data/output/<комплект>/`):
- `doe.png` — фазовый ДОЭ, PNG 128×128, 8 бит, grayscale, 0 = −π, 255 = +π;
- `restored_1..4.png` — восстановление дифракцией Френеля (модуль |K|, нормировка на максимум);
- `metrics.csv` — SSIM и Пирсон по каждой паре;
- `/data/output/results.csv` — средние SSIM, Пирсон и время синтеза по каждому комплекту и итог.

Проверка на встроенных примерах: `docker run --rm -v "<папка для результатов>:/data/output" meefee-doe --input examples --output /data/output`.

Образ работает на процессоре (видеокарта не нужна). ДОЭ синтезирует только нейросеть, за один проход. Сборка и запуск образа проверяются автоматически (GitHub Actions, вкладка Actions).

## Результаты

Тестовые изображения — цифры 1–4 (`examples/`). Метрики посчитаны по сохранённому 8-битному `doe.png`, амплитуды нормированы на максимум. RTX 5060.

| Метод | КК (Пирсон) | ИСС (SSIM) | Время |
|---|---|---|---|
| Гершберг–Сакстон, 300 итераций (для сравнения) | 0,766 | 0,182 | 2,56 с |
| **Нейросеть DOENet** (итоговый метод) | 0,609 | **0,726** | **0,01 с** |

20 случайных наборов по 4 изображения (`benchmark.py`, те же наборы для всех методов):

| Метод | КК | ИСС | Время |
|---|---|---|---|
| Гершберг–Сакстон, 300 итераций (для сравнения) | 0,588 | 0,123 | 2,6 с |
| **Нейросеть DOENet** | 0,398 | **0,584** | **0,008 с** |

Нейросеть в **~330 раз быстрее** классического итеративного метода и даёт ИСС в **4–4,7 раза выше**. Классика даёт высокий КК, но изображение «рассыпается» на спеклы (низкий ИСС).

Обученная модель: `models/best.pt` (6,3 млн параметров).

## Идея решения

1. **Нейросеть DOENet** (U-Net, как в DeepCGH, Eybposh et al., Optics Express 2020) получает 4 изображения и сразу выдаёт маску ДОЭ за миллисекунды.
2. **Обучение без готовых ответов (физически-информированное).** Сеть предлагает маску, затем дифференцируемая модель Френеля восстанавливает 4 изображения, и ошибка считается **прямо по метрикам кейса** на модуле поля |K| с нормировкой на максимум (как при проверке): (1 − КК) + 0,5·(1 − ИСС). Вес ИСС задаётся `--w-ssim` (меньше — выше КК, больше — выше ИСС). Ошибки 4 плоскостей возводятся в квадрат, поэтому сеть сильнее подтягивает самую плохую картинку и качество распределяется ровно.
3. **ДОЭ выдаёт только нейросеть, за один проход.** Никакой итеративной оптимизации маски под конкретные входные изображения нет (по правилам кейса). Гершберг–Сакстон считается только для сравнения.
4. **Сеть с физикой внутри (DOENetPhys, `--stages 2`).** После первой маски физический слой Френеля (без обучаемых параметров) показывает сети, что получается в 4 плоскостях, и следующие обученные блоки вносят поправку. Число блоков фиксировано, веса обучены заранее — это одна сеть с физикой внутри, а не подбор под картинки.
5. **Всё как при сдаче.** Метрики считаются по сохранённому 8-битному `doe.png` (0 = −π, 255 = +π), то есть уже после квантования фазы.

Почему задача трудная: плоскости отстоят всего на 1,2 мм, поэтому изображения из соседних плоскостей подсвечивают друг друга. Это физический предел, одинаковый для всех решений. Выигрывает метод, который лучше оптимизирует именно КК и ИСС.

## Установка

Нужен **Python 3.12** (на 3.14+ PyTorch может ещё не выйти). На Windows: `py install 3.12`.

```
py -3.12 -m venv .venv
.venv\Scripts\activate            (Mac/Linux: source .venv/bin/activate)
pip install -r requirements.txt          (для интерфейса ещё: pip install -r requirements-app.txt)
```

PyTorch выбирается под ваше железо:

| Железо | Команда |
|---|---|
| NVIDIA RTX 50xx (5060, 5070…) | `pip install torch --index-url https://download.pytorch.org/whl/cu128` |
| NVIDIA RTX 20xx/30xx/40xx, GTX 16xx | `pip install torch --index-url https://download.pytorch.org/whl/cu126` (или cu128) |
| AMD Radeon на Linux | сборка ROCm, команда на pytorch.org (Get Started → ROCm) |
| Mac на Apple M1–M4 | `pip install torch` (будет использован mps) |
| Без видеокарты / AMD или Intel на Windows | `pip install torch` (будет процессор: обучение медленнее, решение работает) |

Устройство выбирается автоматически: перед работой видеокарта проверяется на реальном расчёте, и если что-то не поддерживается, берётся процессор. Принудительно задать устройство можно так: `set DOE_DEVICE=cpu` (Windows) или `export DOE_DEVICE=cpu`.

## Запуск по шагам

```
python selftest.py                       # 1. всё ли работает (все строки OK)
python train.py                          # 2. (необязательно) своё обучение → checkpoints/best.pt; без него берётся models/best.pt
python infer.py --input input --output output   # 3. решение: комплекты по 4 картинки → ДОЭ (как в Docker)
python solve.py --dir input_images       #    один комплект + сравнение с классикой и картинка summary.png
python benchmark.py                      # 4. сравнение методов → benchmark.png для презентации
python app.py                            # 5. интерфейс в браузере
```

- Дольше обучение — лучше результат: `python train.py --steps 60000` (на ночь). Прервали — `python train.py --steps 60000 --resume`.
- Мощнее сеть: `--base 48`.
- Подмешать похожие картинки (если организаторы выдадут свои): `--images папка`.
- Сеть с физикой внутри (дообучение поверх готовой): `python train.py --init models/best.pt --stages 2 --steps 15000 --lr 2e-4`.
- `doe/optimize_np.py` и `refine` в `doe/physics_torch.py` — исследовательские инструменты (сравнение с итеративной оптимизацией), в итоговом решении не используются.

## Что сдавать (results/<время>/final)

| Файл | Формат |
|---|---|
| `doe.png` | ДОЭ 128×128, 8 бит, одноканальный, 0 = −π, 255 = +π |
| `restored_1..4.png` | восстановленные изображения 128×128, 8 бит, одноканальные (расчёт Френеля) |
| `metrics.csv`, `metrics.json` | КК (Пирсон) и ИСС для каждой из 4 пар |

Дополнительно: `summary.png` (картинка для слайдов), `methods.csv` (сравнение всех методов), `all_methods/` (результаты каждого метода).

**Про ИСС.** Считаем двумя способами: стандартный оконный SSIM (гауссово окно 11×11, σ = 1,5, как в skimage/MATLAB) — колонка `ИСС_SSIM`, и по формуле со слайда по всему изображению — колонка `ИСС_по_формуле_слайда`. C1 = (0,01·255)², C2 = (0,03·255)².

**Правила (ответы экспертов).** Итоговый ДОЭ синтезирует нейросеть; итеративная доводка маски под входные изображения не допускается. Физические модели внутри сети и классические методы для данных допустимы.

**Как сравниваются изображения (ответ эксперта).** Сравниваются амплитуды: по условию сохраняются модули значений |K|. Каждое изображение (исходное и восстановленное) перед сравнением нормируется на максимум, максимум становится 1. Восстановленный png = |K| / max|K| · 255.


## Набор данных

Обучающие изображения (20 000 шт.: цифры, буквы, фигуры, кольца, точки, полутоновые пятна) генерируются кодом `doe/data.py` — по тому же зерну получается точно тот же набор, поэтому в репозиторий он не выкладывается (около 330 МБ). Создаётся автоматически при первом запуске `train.py`.

## Что проверено

- Формула со слайда и упрощённый расчёт дают одинаковую интенсивность. 8-битное квантование фазы даёт ошибку ≤ π/255. Метрики на одинаковых картинках равны 1 (`test_np.py`).
- Аналитические градиенты совпадают с численными.
- На случайных наборах (модуль поля, нормировка на максимум): Гершберг–Сакстон КК 0,593 / ИСС 0,144, оптимизация по метрикам КК 0,555 / ИСС 0,507.
- PyTorch-часть сверяется с numpy-частью в `selftest.py` на вашем компьютере.
